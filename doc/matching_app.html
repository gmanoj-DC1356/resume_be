The matching app

matching is a Django app, "Module 3 - Resume matching engine & knowledge base". Today it implements only the ingestion half of a RAG-style pipeline: resume PDFs go in, are chunked and embedded, and are stored in Milvus. The query/matching half and the real API endpoints do not exist yet.

Modules

PathRole
conf.py Frozen MatchingSettings dataclass read from environment variables: Milvus URI, token, DB name and collection; embedding model (default BAAI/bge-large-en-v1.5, dim 1024) and BGE query prefix; index type (FLAT or HNSW); chunk size (300 words) and overlap (40); PDF limits (10 MB, 20 pages); embed batch size. Milvus variables use a MATCHING_ prefix because pymilvus parses MILVUS_URI itself on import. get_matching_settings() is the accessor.
ingestion/pdf_loader.py iter_pdf_paths yields .pdf files directly under the root, skipping symlinks, oversize files and paths resolving outside the root. load_pdf checks the %PDF magic bytes and page limit, extracts text with pypdf, and returns a LoadedPdf whose resume_id is the first 16 hex chars of the file's SHA-256. Scanned PDFs with no text are rejected (OCR out of scope).
ingestion/chunker.py split_sections detects headings by regex (summary, experience, skills, education); text before the first heading is "summary". chunk_text slides a word window (max_words, overlap_words) over each section and returns Chunk(chunk_idx, section, text) objects. It raises an error if overlap ≥ size.
embedding/embedder.py Embedder wraps SentenceTransformer (lazy import) and checks the model dimension against EMBED_DIM. embed_documents returns L2-normalised vectors with no prefix; embed_query adds the BGE query prefix. One class serves ingestion and queries so vectors stay comparable.
store/milvus_store.py get_client uses Milvus Lite (local file) for a path URI, or a server for http(s)://. ensure_collection builds the schema and COSINE index (optionally dropping first with reset). assert_model_compatible refuses to mix vectors from different models. resume_exists checks by hash, validating the ID against ^[0-9a-f]{16}$ before using it in the filter. upsert_chunks writes rows.
ingestion/pipeline.pyingest_folder orchestrates the steps and returns an IngestReport (ingested, skipped, failed, chunks).
management/commands/ingest_resumes.pyCLI entry point.
views.py / urls.pyPlaceholder GET ping/ endpoint under app_name="matching".
models.py, admin.py, apps.pyDjango boilerplate; models.py and admin.py are empty.
tests.py, test_chunker.pytests.py is a stub; test_chunker.py is 31 lines.

End-to-end execution

python manage.py ingest_resumes --input-dir data/resumes [--reset]
  1. Command (ingest_resumes.py): parses arguments, loads settings, calls ingest_folder(...). NotADirectoryError and RuntimeError become a clean CommandError.
  2. Setup (pipeline.py): connect with get_client; ensure_collection creates schema and index if missing; assert_model_compatible checks existing data against the configured model; Embedder loads the model.
  3. Per PDF (loop over iter_pdf_paths):
    1. load_pdf extracts text and computes the content-hash resume_id.
    2. resume_exists skips already-ingested files. Ingestion is idempotent and renamed files are still recognised.
    3. chunk_text produces section-aware, overlapping chunks.
    4. embed_documents produces normalised vectors in batches.
    5. Rows are built (filename truncated to 256, text to 8192) and written with upsert_chunks.
    6. Any exception is caught per file, logged without resume text, and the file is added to report.failed; one bad PDF does not stop the run.
  4. Report: prints Ingested N resumes (M chunks), skipped K unchanged, failed F and lists failed files on stderr.

Gaps and notes

  • No retrieval yet. embed_query and the query prefix are ready, but milvus_store has no search function and the views/urls hold only ping.
  • Matching logic is not written: no scoring and no job-description-to-resume flow.
  • Security. The resume_exists filter uses an f-string, but the ID is regex-validated first. The Milvus token comes from the environment only (keep it in .env or a secrets manager). Resumes contain personal data: ingest only synthetic or approved data and keep data/milvus_resumes.db out of version control.
  • Smaller issues. Headings must match a whole line, so "Work Experience" is not detected (the regex has "work history" only); "projects" maps to experience. assert_model_compatible queries with filter="", which some Milvus versions reject; verify against your pymilvus version. Settings defaults are read at import time, so env changes need a restart. load_pdf reads the file twice (bytes, then PdfReader); harmless.

Based on a code read only; the code and tests were not run. Run SAST, dependency scanning and human review before production use.
